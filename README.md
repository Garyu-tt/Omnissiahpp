# ⚙ Omnissiah++ (Омниссия++)

**Религиозно-бюрократический диалект C++ для Адептус Механикус.**

Это **реально работающий прототип компилятора-транспайлера**, а не макет. Исходный код на Omnissiah++ (`.omn`) преобразуется в C++20 и компилируется установленным `g++`/`clang++`. Допускается смешивать ритуальные русскоязычные конструкции с обычным синтаксисом C++, включая классы, шаблоны, стандартную библиотеку и RAII.

## R04: самокомпиляция через структурное AST

Нативный компилятор теперь способен **разбирать собственный исходник** в
**структурное дерево без потери исходных данных** (`source-ast`), восстанавливать
исходные байты из дерева и собирать следующую версию себя (`source-build`).
Bootstrap stages 1→2→3 используют именно этот путь и сверяются с прежним
эмиттером; Python используется только как первичная стадия и независимый
эталон для проверок. **43 автоматических теста** (состояние R04).

```sh
bash scripts/bootstrap.sh build/bootstrap
build/bootstrap/omnic-stage3 source-ast bootstrap/omnissiah_selfhost.omn -o build/self.json
build/bootstrap/omnic-stage3 source-emit bootstrap/omnissiah_selfhost.omn -o build/self.cpp
build/bootstrap/omnic-stage3 source-run examples/hello.omn
# Cross-compiler bootstrap (если установлен clang++)
CXX=clang++ bash scripts/bootstrap.sh build/clang-bootstrap
```

Структурное AST включает все токены, пробельные символы, комментарии, директивы
препроцессора, литералы и вложенные группы `()`, `{}`, `[]`. Узлы содержат
байтовые позиции `start/end`, строки и колонки; незакрытые, неподходящие
скобки и чрезмерная вложенность диагностируются как `OMN130`–`OMN132`.
Генератор получает исходник **обратным обходом дерева**, затем применяет общий
с классическим транспайлером анализ ритуалов и подстановки ключевых слов.

**Граница R04:** это lossless *structural* AST (дерево токенов/групп), а не
полный грамматический AST C++20. Преобразования по-прежнему лексические, а
семантику программы окончательно проверяет GCC/Clang. R03 Core AST остаётся
отдельным строгим грамматическим анализатором ограниченного подмножества.
Следующая цель — постепенно переносить грамматические объявления, выражения и
проверку типов в общий AST без потери совместимости с C++20.

## R03: нативный AST и отдельный компилятор Core

Компилятор из [`bootstrap/omnissiah_selfhost.omn`](bootstrap/omnissiah_selfhost.omn)
теперь содержит **синтаксический анализатор и генератор кода**, написанные
на самом Omnissiah++. Новый режим **не просто переименовывает токены**:
парсер строит дерево AST, а генератор выпускает C++20 из узлов этого дерева.

```bash
bash scripts/bootstrap.sh build/bootstrap

# Посмотреть проверяемое AST в формате JSON
build/bootstrap/omnic-stage3 ast examples/core_syntax.omn -o build/core.ast.json

# Сгенерировать C++20 из AST
build/bootstrap/omnic-stage3 core-emit examples/core_syntax.omn -o build/core.cpp

# Скомпилировать / исполнить программу через AST backend
build/bootstrap/omnic-stage3 core-build examples/core_syntax.omn -o build/core
build/core
build/bootstrap/omnic-stage3 core-run examples/core_syntax.omn
# R03 core: 10
```

**Подмножество Core R03:** объявления функций/переменных/простых классов и
структур, типы и параметры, блоки, `if/else`, `for`, `while`,
`return/break/continue`, вызовы, поля и индексы, унарные/бинарные операторы,
тернарный оператор, литералы и ритуалы. В AST сохраняются строка и колонка.

**Граница поддержки:** `ast`, `core-emit`, `core-build` и `core-run` принимают
только это подмножество. Полный C++20, сложные шаблоны, конструкторы,
`try/catch`, лямбды, макросы и исходник самого компилятора в нём **пока не
поддержаны**. В Core допускаются обычные директивы `#include`, но `#define`
и остальные директивы Core-генератор отклоняет (`OMN116`), не удаляя их молча.
Для более сложного C++ используйте обратносовместимые команды `emit`, `build`
и `run` из R02. Команда `check` по-прежнему проверяет только ритуалы; **`ast`
проверяет грамматику Core**, а `core-build` ещё и валидность полученного C++.

R03 сохраняет трёхпоколенную самокомпиляцию, но bootstrap собственного
исходника пока идёт через совместимый транспайлер R02, а не через Core AST.
Это следующий самостоятельный этап работ, **не выполненный** в R03.

## R02: самокомпиляция (self-hosted compiler)

**Omnissiah++ теперь компилирует сам себя.** Исходник нативного
компилятора — [`bootstrap/omnissiah_selfhost.omn`](bootstrap/omnissiah_selfhost.omn).
Python-компилятор R01 нужен только для первичной сборки. После этого нативный
бинарник самостоятельно транслирует `.omn` и вызывает системный C++ компилятор.

```bash
# Python -> native stage 1 -> self-compiled stage 2 -> stage 3;
# проверка побайтовой стабильности генерируемого C++
bash scripts/bootstrap.sh build/bootstrap

# Запуск без Python
build/bootstrap/omnic-stage3 run examples/hello.omn
build/bootstrap/omnic-stage3 build examples/memory.omn -o build/memory
```

Подробная инструкция и границы самокомпиляции:
[`bootstrap/README.md`](bootstrap/README.md).
Это **самокомпилируемый транспайлер**, а не собственный backend машинного кода:
для компоновки бинарников по-прежнему используется `g++`/`clang++`.

## Запуск классического R01

Нужно: **Python 3.10+** и **компилятор C++** (`g++` либо `clang++`). Дополнительные библиотеки Python не требуются.

```bash
# Запустить пример (компиляция и выполнение)
python3 omnissiah.py run examples/hello.omn

# Скомпилировать в исполняемый файл
python3 omnissiah.py build examples/memory.omn -o /tmp/relic
/tmp/relic

# Только проверить ритуалы
python3 omnissiah.py check examples/hello.omn

# Посмотреть сгенерированный C++
python3 omnissiah.py emit examples/hello.omn -o /tmp/hello.cpp

# Сохранить сгенерированный C++ во время сборки
python3 omnissiah.py build examples/hello.omn -o /tmp/hello --keep-cpp /tmp/hello.cpp

# Если используете clang++
python3 omnissiah.py run examples/hello.omn --cxx clang++
```

## Пример

```cpp
ВО_ИМЯ_ОМНИССИИ;
ОСВЯТИТЬ процессор;
ВОССЛАВИТЬ машинный_дух;

ЛИТАНИЯ главная() {
    ЦЕЛОЕ количество = 3;
    СВЯЩЕННЫЙ_ЦИКЛ (ЦЕЛОЕ i = 0; i < количество; ++i) {
        ЕСЛИ_ВОЛЯ_ОМНИССИИ (i % 2 == 0) {
            МОЛИТВА("Слава Омниссии! ", i);
        } ИНАЧЕ {
            МОЛИТВА("Машинный дух ворчит.");
        }
    }
    ВЕРНУТЬ 0;
}
ДА_БУДЕТ_ВОЛЯ_МАШИНЫ;
```

## Священные правила (действительно проверяются)

| Ритуал | Смысл |
|---|---|
| `ВО_ИМЯ_ОМНИССИИ;` | Обязательный первый оператор (директивы `#include` могут идти раньше) |
| `ОСВЯТИТЬ процессор;` | Требуется до объявления `главная()`/`main()` |
| `ВОССЛАВИТЬ машинный_дух;` | Требуется при `МОЛИТВА`, `std::cout`, `std::cin`, `printf`, базовом файловом I/O |
| `ОСВЯТИТЬ память;` | Требуется при явном `new`, `delete`, `malloc`, `make_unique`, `make_shared` |
| `ДА_БУДЕТ_ВОЛЯ_МАШИНЫ;` | Обязательный последний оператор |

Все ритуалы записываются **на уровне файла**, до функций и прочих объявлений. Нарушение выдаёт `OMNxxx` с номером строки, например:

```text
example.omn:5:5: error OMN021: ввод-вывод требует ВОССЛАВИТЬ машинный_дух;
```

### Словарь

| Omnissiah++ | C++ |
|---|---|
| `ЛИТАНИЯ главная()` | `int main()` |
| `ЦЕЛОЕ`, `ДРОБЬ`, `СТРОКА`, `ЛОГИКА`, `НИЧТО` | `int`, `double`, `std::string`, `bool`, `void` |
| `ИСТИНА`, `ЛОЖЬ`, `АВТО`, `ПОСТОЯННО` | `true`, `false`, `auto`, `const` |
| `ЕСЛИ_ВОЛЯ_ОМНИССИИ`, `ИНАЧЕ` | `if`, `else` |
| `СВЯЩЕННЫЙ_ЦИКЛ`, `ПОКА_ДУХ_НЕ_УСМИРЕН` | `for`, `while` |
| `ВЕРНУТЬ`, `ПРЕРВАТЬ`, `ПРОДОЛЖИТЬ` | `return`, `break`, `continue` |
| `КЛАСС`, `СТРУКТУРА`, `ШАБЛОН` | `class`, `struct`, `template` |
| `ПУБЛИЧНО`, `ЧАСТНО`, `ЗАЩИЩЕНО` | `public`, `private`, `protected` |
| `НОВОЕ`, `УДАЛИТЬ` | `new`, `delete` |
| `МОЛИТВА(...)` | `omni::prayer(...)`, печатает значения с переводом строки |

Остальные конструкции пишутся на обычном C++: например, `typename`, `std::vector`, `try/catch`, лямбды и наследование.

## Испытание техноереси

```bash
python3 omnissiah.py check examples/heresy.omn
# examples/heresy.omn:6:5: error OMN021: ввод-вывод требует ВОССЛАВИТЬ машинный_дух;
```

## Тёмная эра технологий

```bash
python3 omnissiah.py run examples/hello.omn --dark-age
```

Флаг `--dark-age` **отключает требование обязательных ритуалов** (не проверку синтаксиса). Можно даже писать C++-подобный код вообще без обрамления `ВО_ИМЯ...` и `ДА_БУДЕТ...`, но остаётся возможность русских ключевых слов. Компилятор печатает предупреждение о техноереси.

## Тесты

```bash
python3 -m unittest discover -s tests -v
```

Есть тесты синтаксиса, ошибок ритуалов, защиты строк/комментариев, сборки C++ и правильных номеров строк ошибок.

## Важные технические ограничения и меры безопасности

- Это **транспайлер поверх настоящего C++**, не самостоятельный backend или полная новая спецификация стандарта C++.
- Гейты на операции — **лексические проверки известных вызовов**, а не статический анализ / sandbox. Они не гарантируют обнаружение I/O/alloc через макросы, указатели функций, пользовательские обёртки или сторонние библиотеки.
- `ОСВЯТИТЬ память` не требуется для неявных аллокаций внутри STL.
- Ключевые слова не заменяются внутри строк, комментариев, `#include` и иных препроцессорных директив; для макросов разумнее использовать обычные токены C++.
- `check` проверяет лишь ритуалы и лексический разбор; **полная проверка C++ осуществляется через `build` или `run`**.
- `build` и `run` исполняют реальный компилятор, а `run` — полученный бинарник. **Не запускайте недоверенный исходный код без изоляции.**

Архитектура: UTF-8 лексер → анализ ритуалов → безопасные для строк/комментариев замены токенов → C++20 с `#line` → `g++`/`clang++`. Формат исходного файла: UTF-8, расширение `.omn` / `.opp` (не строгое).

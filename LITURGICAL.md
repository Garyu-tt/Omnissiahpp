# Liturgical Compiler R01: добровольная техноересь наоборот

`liturgical_compiler.py` — **отдельный** режим Omnissiah++, который не меняет обычные `omnissiah.py` и нативный self-hosted `omnic`. Для обычных программ молитва при запуске не нужна.

Для литургической сборки обязательны четыре разновидности молитв, **по десять разных текстов** в каждой. Каждая молитва — приблизительно 300 символов (276–315 на момент R01).

| Стадия | Когда требуется | Правило |
| --- | --- | --- |
| Очищение (purification) | Перед `check`, трансляцией и сборкой | Точный повтор показанной молитвы |
| Компиляция (compilation) | Перед созданием объектного файла | Точный повтор новой молитвы |
| Компоновка (linking) | Перед связыванием объектного файла | Точный повтор новой молитвы |
| Запуск (launch) | **При каждом вызове готового бинарника** | Точный повтор одной из десяти молитв |

На каждом этапе выбирается случайная молитва своей разновидности, печатается полностью, после чего её необходимо ввести **дословно**. Ошибка, EOF или отмена останавливает этап с кодом `77`. Пробелы и регистр значимы. Текст молитвы не хранится как пароль: это ритуал подтверждения, **не механизм защиты исполняемого файла от атакующего**.

## Пример

```sh
python3 liturgical_compiler.py check examples/hello.omn
python3 liturgical_compiler.py build examples/hello.omn -o build/hello-blessed
./build/hello-blessed
./build/hello-blessed   # снова новая обязательная литания запуска
```

Компилятор делает реальную двухэтапную сборку `g++ -c` и `g++ -o` после исходного `omnissiah.py emit`. Поддержаны `--cxx`, `--std`, `--optimize`, `--dialect` (включая `binary-cant`), `--keep-cpp`. `run` сначала выполняет все ритуалы сборки, а затем запускает бинарник с новой молитвой:

```sh
python3 liturgical_compiler.py run examples/hello.omn
```

Никаких `--skip-prayer`, `--dark-age` и переменных окружения для обхода проверки в этом интерфейсе нет. Встроенная точка входа запускается даже при непосредственном исполнении бинарника, без Python или исходного компилятора.

Поддерживаются обычные формы `int main()` и `int main(int argc, char** argv)`. Для `run` аргументы приложения передаются через `--arg`. Исходный `main` переименовывается при генерации отдельного C++ файла. Это экспериментальный инструмент поверх C++ и не криптографическая защита от модификации/перепаковки бинарника.

## Тесты

```sh
python3 -m unittest discover -s tests -p 'test_liturgical_compiler.py' -v
```

Проверяются размеры каталога, длины молитв, отсутствие вмешательства в обычный компилятор, отказ при отсутствии/ошибке ввода и реальный запуск C++ бинарника после правильной молитвы.
